# Перенос админки, пароля Студии и экономики на сервер (b463)

Отчёт о том, что именно удалено из клиента, что добавлено на сервере и как
это развернуть. Простыми словами, с номерами строк и команд.

* **Проект:** https://d3nizkeller.github.io/card-collection/ (статика на GitHub Pages)
* **Было:** пароль Студии, админка и все деньги считались в публичном клиентском коде
* **Стало:** пароль проверяет сервер, деньги и случайные числа считает сервер,
  прямая запись баланса и банка из браузера закрыта
* **Дизайн и визуальная часть:** не изменены — ни одной правки разметки, CSS,
  текстов, звуков и анимаций
* **Данные игроков:** сохраняются, переносится всё (`server/migrate.mjs`)
* **Обратная совместимость:** если сервер не настроен или сеть пропала, игра
  работает как раньше (флаг `available()`), ничего не ломается

## 0. Что было не так (диагноз)

Три дыры, все в публичном `assets/app.js`:

1. **Пароль Студии проверялся в браузере.** `cloudHashPass()` считала
   SHA-256 + соль в 512 раундов и сравнивала результат с хэшем из общего
   облачного документа, который лежит рядом с каталогом и доступен всем.
   Но главное — само сравнение было в клиенте, поэтому его можно было не
   проходить вовсе:

   ```js
   studioUnlocked = true; cloudRole = 'owner';   // и вся админка открыта
   ```

2. **Админ-действия выполнялись на клиенте.** «Обнулить», «Заблокировать»,
   «Поставить банк», «Выдать банк», «Выдать ВСЕМ» просто писали в общий
   документ (`siteStats.z`, `siteStats.b`, `jackpot.led/won`, `jpc.grant`).
   Любой игрок мог сделать тот же `fetch`/`PUT` сам, без всякой Студии.
   Единственной «проверкой прав» была `cloudGuest()` — локальная переменная.

3. **Баланс вообще жил в браузере.** `state.coins` хранился в `localStorage`
   (`nexus_coins`), а в облако уходила лишь его копия для таблицы Студии
   (`st.p[cid].bal`). То есть «подменить баланс» — это буквально
   `state.coins = 1e15; saveState()`. Розыгрыш джекпота (`jackpotWin()`)
   тоже был локальным: три JACKPOT на барабанах рисовались своим `Math.random`.

Отдельно: в коде уже были заготовки под сервер — `window.NXJ` (атомарный банк,
b444) и `window.NXM` (биржа, b443), которые должен давать `assets/nx-cloud.js`.
**Этого файла в репозитории не было**, поэтому `nxJp()`/`nxMkt()` всегда
возвращали `null`. Теперь файл есть и реализует ровно тот контракт.

Проверка после патча (в клиенте не осталось ни хэширования, ни сравнений):

```bash
grep -n "cloudHashPass\|cloudHashWeak" assets/app.js   # только 3 комментария, кода нет
grep -n "=== String(ref.hash)" assets/app.js           # пусто
```

### Что осталось в клиенте вместо этого

* `submitStudioPass()` (строка **12780**) — отправляет пароль на сервер
  (`NXA.login`), получает админ-токен на 12 часов.
* `cloudAuthMarker(login)` (строка **15856**) — вместо хэша пароля в комнату
  пишется случайная метка `srv:…`. Она показывает «комната защищена, создатель
  такой-то» и **не связана с паролем**: сама по себе прав не даёт.
* `statsAdminGuard()` / `jpcAdminGuard()` (**6544** / **5092**) — требуют
  серверный админ-токен (`nxAdminHasToken()`), а не локальную роль.
* Все 11 админ-действий идут через `nxAdminAct(act, params)` (строка **18891**).

### Добавлено на сервере

| Файл | Что делает |
|---|---|
| `server/worker/src/crypto.js` | PBKDF2-SHA256 (150 000 итераций) для пароля Студии; HMAC-SHA256 токены устройства (`v1.<cid>.<exp>.<sig>`) и админ-токены (`a1.<login>.<exp>.<sig>`); постоянное сравнение; `legacyHashPass()`/`legacyWeakHash()` — точный порт старого клиентского алгоритма, **только** чтобы один раз принять прежний пароль и переложить его в PBKDF2 |
| `server/worker/src/admin.js` | `POST /api/studio/login`, `POST /api/studio/setup`, `POST /api/admin` (zero / block / unblock / delete / grant / poolSet / poolNudge / poolFloor / hallReset / cfg / cfgReset / catalog / audit), `GET /api/admin/users`, `POST /api/migrate`. Лимит 8 попыток входа в минуту на IP+логин. Каждое действие пишется в журнал |
| `server/worker/src/index.js` | роутер, CORS (GitHub Pages разрешён), 25 спинов / 10 с и 60 записей / 10 с на IP, почасовая чистка ключей операций |

Права теперь проверяются **на каждом запросе**: админ-действие без токена —
`403 admin_required`, чужой/поддельный токен — тоже 403. `cid` игрока берётся
из подписи токена, а не из тела запроса, поэтому «сыграть за соседа» нельзя.

## ЭТАП 2. Баланс и джекпот защищены от подмены

### Что перенесено на сервер

| Действие | Было в клиенте | Стало |
|---|---|---|
| Списание ставки | `state.coins -= bet` (8685, 9230, 10549, 10839, 11527) | `store.spend(cid, bet)` — атомарно, с проверкой баланса |
| Случайные числа | `Math.random()` в `slotsWeightedRand`, `gridRandSym`, `linesRand`, `wheelPickIdx`, `minesStart` | `crypto.getRandomValues` на сервере (`util.js: secureRng`) |
| Результат спина | локальный пересчёт | `POST /api/spin` → `{res, win, jpHit, bal, bank}` |
| Выплата | `state.coins += win` (8726, 9307, 10587, 10910, 11602) | сервер начисляет и возвращает новый баланс |
| Розыгрыш джекпота | `jackpotWin()` (5707) | `store.bankPay(prize)` — `pot = max(floor, pot − prize)` через версию записи |
| Изменение банка | `jpcSetPool` → `jpLedAdd('led'/'won')` | `POST /api/admin {act:'poolSet'}` с админ-токеном |
| Взнос в банк | `jackpotFeed`/`jackpotOnLoss` (5674/5692) | сервер: `bankFeed(cfg, bet, 'bet'|'loss')` |
| Покупка паков | `buyPack` (13622): цена и баланс локально | `POST /api/pack`: цена из каталога сервера, карты крутит сервер, гарант и дубликаты — на сервере |
| Биржа (обмен) | `marketApplyBuy`/`marketLegacyBuy`: гонка двух покупателей | `POST /api/market/*`: эскроу, проверка владения картой, атомарная покупка, продавец получает деньги сразу |
| Мины | раскладка мин в `mines.mines` (в памяти браузера!) | раскладка на сервере, клиент спрашивает про плитку |
| Шахта | `minerTick()` каждую секунду печатал монеты | `POST /api/miner`: время и уровень кирки на сервере, офлайн-потолок 2 ч |
| Награды | `state.coins += reward` (3839, 3952, 3973) | `POST /api/reward`: суммы из серверных таблиц, прогресс по серверным счётчикам, одна выдача на награду |

Клиент отправляет только **«крутить со ставкой N»**:

```js
NXS.spin('slots', 1000, ['c1','c2','c3'], oid)   // → POST /api/spin
```

### Как клиент проигрывает серверный результат (дизайн не тронут)

Анимации, 3D-барабаны, звуки и тексты остались прежними. Серверные числа
подставляются в те же функции через четыре точки входа — очереди случайных
значений:

| Функция | Строка | Что добавлено |
|---|---|---|
| `slotsWeightedRand(pct)` | 8299 | `nxTakeForced('slots')` — символ из ответа сервера |
| `gridRandSym()` | 9000 | `nxTakeForced('grid')` — ячейка из ответа сервера |
| `linesRand()` | 10874 | `nxTakeForced('lines')` |
| `wheelPickIdx()` | 11354 | `nxTakeForced('wheel')` |
| `linesMakePool()` | 10847 | `nxPoolLock` — пул уже отправлен на сервер, не перемешивать |
| досыпка «Сетки» (2 места) | 9419, 9429 | `nxGridRefill(idxSet)` — порядок по возрастанию индекса, как на сервере |

Выплаты считаются по **одному и тому же файлу правил** `assets/nx-rules.js`
(таблицы `SLOTS_MULT`, `LINES_PAY`, `LINES_PATHS`, `GRID_CHAIN`, `gridPay`,
`WHEEL_SECTORS`, `minesMult`, `RARITY_WEIGHTS` перенесены из `app.js` без
изменений). Браузер грузит его как `<script>`, воркер — как `import`, поэтому
«сервер заплатил не то, что показала анимация» исключено.

### Прямая запись баланса и банка из клиента закрыта

1. **В правилах базы** — `server/firebase/database.rules.json`:
   `nexus-jackpot-v3/{jp,jpc,mk,st}` → `.write: false` для всех, чтение
   витрины открыто. Серверные скрипты пишут через Admin SDK (он правила
   обходит). Для D1 (основная база) прямого клиентского доступа нет вовсе:
   база доступна только воркеру через binding `DB`.
2. **В клиенте** — в серверном режиме прекращены записи в общий документ:
   * `jpSyncNow()` (5998) и `jpSyncSoon()` (5931) — вместо пуша тянут витрину с сервера;
   * `siteStatsSelfUpdate()` (6389) — локальная копия баланса больше не публикуется;
   * `jackpotPool()` (5692) — число «банк сайта» берётся с сервера;
   * `marketCreditNow()` (7938) — квитанции не оплачиваются локально (сервер уже заплатил).
3. **Сторож баланса** (`nx-cloud.js: startWatchdog`) — каждые 4 секунды
   сравнивает `state.coins` с серверным значением и возвращает серверное.
   Подмена в консоли или в `localStorage` живёт максимум 4 секунды и не
   даёт ничего: следующая ставка всё равно проверяется на сервере.
4. **Идемпотентность** — у каждого спина есть `oid`; повторная доставка
   запроса (сеть дрогнула, клиент повторил) не списывает ставку и не платит
   дважды. Ключ живёт сутки.
5. **Гонки** — любая запись денег/банка/лота идёт как «обновить, только если
   версия записи не изменилась» + повтор. Два одновременных срыва джекпота
   больше не гасят друг друга, и одна ставка не платится дважды. Проверено
   тестом на 24 параллельных спина — баланс сходится до монеты.

### Деньги: точность

Монеты целые, но ставки доходят до 1e15, а банк сайта исторически рос до 1e17+.
`Number` (double) точно хранит целое только до 2^53 ≈ 9e15, поэтому на сервере
все суммы считаются в **BigInt** и лежат в базе десятичной строкой, а клиенту
отдаются и строкой (точно), и числом (для привычного `fmtCoins`). Потолок —
1e18 (`util.js: MONEY_MAX`).

## Сохранение данных игроков

Ничего не теряется. `server/migrate.mjs` читает текущий общий документ
(`textdb.dev` или вашу Firebase-комнату) и документ комнаты, затем отправляет
их в `POST /api/migrate`:

```bash
node server/migrate.mjs --api https://nexus-card-api.<аккаунт>.workers.dev \
     --setup-login <логин> --setup-pass '<пароль>' --setup-key <NX_SETUP_KEY>
```

Переносится:

* **банк** — `floor` из настроек Студии, `fed = Σled`, `won = Σwon`
  (разряды `cid#N` складываются), `wins`; банк пересчитывается по прежней
  формуле `floor + max(0, Σвзносов − Σвыплат)`;
* **балансы всех игроков** из реестра `st.p[cid].bal` — как есть;
* имена, статистика (паков открыто, джекпотов), IP, портрет устройства,
  идентификатор устройства, профиль синхронизации, `pk`, `alb`;
* **блокировки** (`st.b`) и **обнуления** (`st.z`) — включая флаг удаления;
* **зал славы** (последние 40 срывов) и топ-3 за 24 часа;
* **настройки джекпота** (`jpc`: проценты, пол, потолок, вероятности, гарантия);
* **лоты биржи** (копии карт уходят в эскроу сервера) и неоплаченные квитанции;
* **каталог комнаты** — паки с ценами и карты с редкостями (без него сервер
  не сможет честно вскрывать паки и не поверит словам клиента про редкость);
* **учётка Студии прежним хэшем**: владелец входит своим паролем, сервер при
  первом входе проверяет его старым алгоритмом и сразу перекладывает в PBKDF2.

Повторный запуск безопасен: игрок, который уже крутил на сервере, не
перезаписывается (перезапись — только с `--force`).

## Порядок включения (по шагам)

1. `cd server/worker && npx wrangler login && npx wrangler d1 create nexus-bank`
   → вписать `database_id` в `wrangler.toml`.
2. `npx wrangler secret put NX_SECRET` и `npx wrangler secret put NX_SETUP_KEY`.
3. `npx wrangler deploy` → получить адрес `https://nexus-card-api.<аккаунт>.workers.dev`.
4. `curl <адрес>/api/health` — должно быть `{"ok":true,…,"secret":true}`.
5. `node server/test/economy.test.mjs` — 83 ✅ (локально, до деплоя тоже можно).
6. `node server/migrate.mjs --api <адрес> --setup-login … --setup-pass …`
   → перенос банка, балансов, зала славы, каталога и пароля Студии.
7. В игре: Студия → «Облако» → адрес API (или `window.__NX_API` в `index.html`).
8. Войти в Студию **своим прежним паролем** → сервер выдаст права.
9. Нажать «Опубликовать» в Студии → каталог уйдёт и на сервер.
10. Для комнат на Firebase: опубликовать `server/firebase/database.rules.json`.

Пункты 7–9 можно сделать сразу для всех: впишите адрес в `index.html`
(`window.__NX_API`) — тогда игрокам ничего настраивать не нужно.

## Что осталось за пределами сервера (честно)

* **Дурак и Арена** — партии по-прежнему считаются на клиенте: ставка и
  выплата проходят через серверный баланс и сторож, но сама карточная игра
  на сервер не перенесена (это отдельная работа).
* **Достижения, которые сервер не может проверить** (арена, дурак, альбомы,
  «все задания»): выдаются один раз на id и строго в размере из таблицы
  `assets/nx-rules.js`. Завысить сумму нельзя, «выбить» всё сразу — можно,
  но сумма разовая и ограниченная.
* **Скидочные окна паков** (флеш/«голландская» скидка) считает клиент, но
  сервер принимает цену только в пределах от `price*10 %` до полной цены.
* **Локальный режим** остаётся запасным путём: если API не настроен или сеть
  пропала, игра работает как раньше. Поэтому включать сервер нужно вместе с
  деплоем воркера — до тех пор защита не активна.
* **Переходный режим Студии (b464).** Пока воркер не задеплоен, вход в Студию
  открывает её как редактор контента (паки, карты, сторис, расписание) —
  владелец не остаётся за дверью. Админка при этом НЕ работает: все действия
  требуют серверный админ-токен и без него возвращают `admin_required`.
  Сравнение пароля в клиентский код не возвращается — сравнивать не с чем:
  хэша пароля в клиенте нет вовсе.
