# Сервер «Коллекционера карт» (b463)

Здесь лежит серверная часть игры: то, что раньше считалось в браузере и
подделывалось в пару строк консоли. Теперь **баланс, ставки, случайные числа,
выплаты, банк джекпота, покупки, биржа и вся админка** — на сервере.

Сайт остаётся статическим (GitHub Pages). Сервер — это один Cloudflare Worker
и база D1 (SQLite). Бесплатного тарифа хватает: 100 000 запросов/сутки и
5 ГБ хранилища, а игра делает 1 запрос на спин.

```
server/
├── worker/
│   ├── src/index.js        роутер, CORS, ограничения частоты
│   ├── src/api.js          вход, витрина, СПИНЫ, мины
│   ├── src/economy.js      паки, шахта, награды, биржа
│   ├── src/admin.js        вход в Студию, действия админки, миграция
│   ├── src/store.js        деньги/банк/лоты: запись через версию (без гонок)
│   ├── src/crypto.js       PBKDF2-пароль Студии, HMAC-токены, крипто-RNG
│   ├── src/driver-d1.js    драйвер Cloudflare D1
│   ├── src/driver-mem.js   тот же интерфейс в памяти — для локальных тестов
│   ├── schema.sql          схема базы (одна таблица kv, создаётся сама)
│   └── wrangler.toml       конфигурация деплоя
├── dev/serve.mjs           локальный сервер на node (без Cloudflare)
├── test/economy.test.mjs   83 проверки экономики — гоняются локально
├── firebase/database.rules.json   правила RTDB: прямая запись денег закрыта
├── migrate.mjs             перенос текущих данных игроков
└── README.md               этот файл
```

Общие правила игры (таблицы выплат, веса, множители, каскады «Сетки») лежат в
**`assets/nx-rules.js`** — этот файл грузит и браузер, и воркер, поэтому
выплаты на сервере и анимация в браузере не могут разъехаться. Таблицы наград
в нём генерируются из `assets/app.js` скриптом `tools/gen_nx_rules_tables.py`.

## 1. Деплой — ОДНА команда (b465)

Нужны бесплатный аккаунт Cloudflare и Node.js 18+. Пошагово для владельца —
**`EASY-SETUP.md`** в корне репозитория.

```bash
npm run nexus          # = node server/setup.mjs
```

Скрипт спросит API-токен Cloudflare, логин и пароль Студии — и сам создаст базу
D1, впишет `database_id` в `wrangler.toml`, сгенерирует `NX_SECRET` и
`NX_SETUP_KEY`, задеплоит воркер, загрузит секреты, проверит `/api/health`,
перенесёт данные игроков и впишет адрес API в `index.html`. Ключи сохранятся в
`server/.nexus.local.json` (в `.gitignore`), поэтому повторный запуск продолжает
с того же места. Флаг `--push` — сразу закоммитить и запушить `index.html`.

Без вопросов (для автоматизации):

```bash
node server/setup.mjs --token <CF_API_TOKEN> --studio-login owner \
     --studio-pass '<пароль>' [--account <ID>] [--skip-migrate] [--push]
```

Токен Cloudflare создаётся с правами **Account → Workers Scripts → Edit** и
**Account → D1 → Edit**; после установки его можно отозвать («Roll») — на
работающий воркер это не влияет.

### Вручную (если хочется по-старому)

```bash
cd server/worker
npx wrangler login                       # откроет браузер, пустит в аккаунт
npx wrangler d1 create nexus-bank        # создать базу → скопировать database_id
```

Впишите полученный `database_id` в `wrangler.toml` (строка
`database_id = "ЗАПОЛНИТЬ_ПОСЛЕ_wrangler_d1_create"`).

```bash
npx wrangler secret put NX_SECRET        # любая длинная случайная строка
npx wrangler secret put NX_SETUP_KEY     # ключ первой регистрации Студии (рекомендуется)
npx wrangler deploy                      # → https://nexus-card-api.<аккаунт>.workers.dev
```

Таблица в базе создаётся сама при первом запросе (`driver-d1.js: ensure`),
поэтому отдельный шаг миграции схемы не нужен. Проверка:

```bash
curl https://nexus-card-api.<аккаунт>.workers.dev/api/health
# {"ok":true,"ts":…,"store":"d1","secret":true}
```

`NX_SECRET` — единственный настоящий секрет: им подписываются токены устройств
и админ-токены. В репозиторий он не попадает (только через `wrangler secret`).
Сгенерировать: `openssl rand -hex 32` или `node -e "console.log(crypto.randomUUID()+crypto.randomUUID())"`.

### Переменные воркера

| Переменная     | Зачем                                                                  |
|----------------|------------------------------------------------------------------------|
| `NX_SECRET`    | **секрет**, подпись токенов. Без него воркер отвечает `server_not_configured` |
| `NX_SETUP_KEY` | необязательный **секрет**: без него первую учётку Студии может создать кто угодно, кто успел первым |
| `NX_ROOM`      | комната по умолчанию, если клиент не прислал свою (`site`)              |
| `NX_ORIGINS`   | дополнительные источники CORS через запятую (GitHub Pages уже разрешён) |

## 2. Подключение игры к серверу

В игре: **Студия → «Облако» → адрес API** (или консолью, один раз на устройство):

```js
localStorage.setItem('nx_api_url', 'https://nexus-card-api.<аккаунт>.workers.dev');
location.reload();
```

Пока адрес не указан, `NXS.available()` = false и игра работает **ровно как
раньше** — на локальной логике. Это же происходит при обрыве связи: ничего не
ломается и не блокируется.

Чтобы сайт сразу знал адрес сервера (без настройки на каждом устройстве),
впишите его в `index.html` до подключения `assets/nx-cloud.js`:

```html
<script>window.__NX_API = 'https://nexus-card-api.<аккаунт>.workers.dev';</script>
<script src="assets/nx-rules.js?v=nxmob186"></script>
<script src="assets/nx-cloud.js?v=nxmob186"></script>
<script src="assets/app.js?v=nxmob186"></script>
```

## 3. Перенос текущих данных игроков

```bash
# 1) создать учётку Студии на сервере и сразу перенести данные
node server/migrate.mjs \
  --api https://nexus-card-api.<аккаунт>.workers.dev \
  --setup-login <ваш логин> --setup-pass '<ваш пароль>' \
  --setup-key <NX_SETUP_KEY>

# 2) если учётка уже есть — просто перенос
node server/migrate.mjs --api https://… --login <логин> --pass '<пароль>'

# посмотреть, что нашлось, ничего не меняя
node server/migrate.mjs --api https://… --dry-run
```

Скрипт читает текущий общий документ (`textdb.dev/api/data/nexus-tcg-jackpot-v3`
или вашу Firebase-комнату) и документ комнаты с каталогом, а затем отправляет
их в `/api/migrate`. Переносятся: банк (пол, Σвзносов, Σвыплат), **балансы всех
игроков**, имена, статистика, IP/устройства, блокировки и обнуления, зал славы,
настройки джекпота, лоты биржи, квитанции, каталог паков и карт, а также
учётка Студии **прежним хэшем** — владелец входит своим паролем, а сервер при
первом входе перекладывает его в PBKDF2.

**b465: две комнаты — не путать.** `--room` задаёт комнату **сервера**
(`x-nx-room`, по умолчанию `site` = общий банк сайта). Каталог паков и карт
лежит в документе комнаты **игры**: `--catalog-room` (по умолчанию берётся из
`assets/app.js` → `CLOUD_DEFAULT_ROOM`, сейчас `7j8uytui`). До b465 адрес
каталога строился из `--room`, поэтому читался пустой `nexus-tcg-room-site` и
перенос шёл без паков, карт и учётки Студии. Там же починено чтение textdb.dev:
на `Accept: application/json` он отвечает двойным JSON, из-за чего переносилось
**0 игроков** при бодром отчёте «✅ готово».

**Защита от обнуления.** Если найдено 0 игроков, 0 записей зала славы, 0 лотов и
нет каталога, скрипт отказывается отправлять миграцию (код выхода 3) и печатает
оба адреса: пустой `/api/migrate` затёр бы банк и балансы. Осознанный обход —
`--allow-empty`.

Повторный запуск безопасен: игрок, который уже крутил на сервере, не
перезаписывается (перезапись — только с `--force`).

Если учётка Студии в старом документе не задана, создайте её через
`--setup-login/--setup-pass` (см. выше).

## 4. Правила Firebase (для комнат на RTDB)

Если вы подключали свою базу Realtime Database, опубликуйте
`server/firebase/database.rules.json`: консоль → Realtime Database → Rules →
вставить → **Publish**. Правила разрешают всем **читать** витрину и каталог и
запрещают кому-либо **писать** банк (`jp`), настройки джекпота (`jpc`),
реестр балансов (`st.p.*.bal`), блокировки (`st.b`, `st.z`) и биржу (`mk`).
Серверные скрипты пишут через Admin SDK — он правила обходит.

## 6. Эндпоинты

| Метод и путь            | Кто зовёт | Что делает |
|-------------------------|-----------|------------|
| `POST /api/boot`        | игра      | вход устройства: выдаёт подписанный токен, баланс, банк, настройки |
| `GET  /api/public`      | игра      | витрина: банк, зал славы, топ-3, число игроков (без токена) |
| `GET  /api/state`       | игра      | баланс, банк, инвентарь, неоплаченные квитанции |
| `POST /api/spin`        | игра      | **«крутить со ставкой N»**: списание, RNG, выплата, банк, джекпот |
| `POST /api/mines`       | игра      | `start` / `pick` / `cashout`; раскладка мин клиенту не отдаётся |
| `POST /api/pack`        | игра      | покупка и вскрытие паков: цена из каталога, карты крутит сервер |
| `POST /api/miner`       | игра      | `claim` (добыча по времени сервера) / `upgrade` (цена кирки) |
| `POST /api/reward`      | игра      | дневная награда, задания, достижения — суммы и прогресс серверные |
| `POST /api/market/list` | игра      | выставить лоты: проверка владения картой + эскроу |
| `POST /api/market/buy`  | игра      | атомарная покупка: деньги списаны, продавец получил сразу |
| `POST /api/market/cancel` | игра    | снять свой лот, копия возвращается из эскроу |
| `GET  /api/market/lots` | игра      | витрина открытых лотов |
| `POST /api/studio/login` | Студия   | **проверка пароля Студии** → админ-токен на 12 часов |
| `POST /api/studio/setup` | Студия   | создать первую учётку / сменить пароль |
| `POST /api/admin`       | Студия    | `zero`, `block`, `unblock`, `delete`, `grant`, `poolSet`, `poolNudge`, `poolFloor`, `hallReset`, `cfg`, `cfgReset`, `catalog`, `audit` |
| `GET  /api/admin/users` | Студия    | реестр игроков для таблицы «Пользователи» |
| `POST /api/migrate`     | скрипт    | перенос текущих данных (см. раздел 3) |
| `GET  /api/health`      | все       | живость, тип хранилища, задан ли секрет |

Все действия админки пишутся в журнал (`audit`) и читаются кнопкой журнала
в Студии: кто, кого, когда и на какую сумму.

## 7. Что осталось за пределами сервера

Честно, чтобы не создавать ложного ощущения брони:

* **Дурак и Арена** — карточные партии по-прежнему считаются на клиенте
  (ставка и выплата проходят через сторож баланса, но сама партия не
  воспроизводится на сервере). Это отдельная работа: нужно переносить
  логику игры в карты.
* **Достижения арены/дурака и альбомов** (`first_win`, `wins_10`, `flawless`,
  `battle_streak3`, `champion_down`, `durak_win`, `durak_streak3`,
  `album_complete`, `albums_3/5/10`, `all_missions`) сервер не может
  проверить по своим счётчикам — они выдаются **один раз на id** и строго
  в размере из таблицы `assets/nx-rules.js`. Завысить сумму нельзя,
  «выбить» все награды сразу — можно, но это разовая и ограниченная сумма.
* **Расписание скидок паков** (флеш-окна, «голландская» скидка) считается на
  клиенте, но сервер принимает цену только в пределах от `price*10 %`
  (максимальная скидка в игре — 90 %) до полной цены. Купить дешевле нельзя.
